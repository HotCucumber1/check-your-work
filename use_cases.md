# Сценарии системы автоматической проверки программных заданий

## 1. Управление заданиями (Assignment Management)

**Акторы:** Professor, Admin.

| ID    | Сценарий                   | Описание                                                                                                     |
|-------|----------------------------|--------------------------------------------------------------------------------------------------------------|
| UC-01 | Создание задания           | Преподаватель создаёт новое программное задание, указывает описание, требования и ограничения.               |
| UC-02 | Настройка срока сдачи      | Преподаватель устанавливает дату и время дедлайна.                                                           |
| UC-03 | Настройка критериев оценки | Преподаватель определяет критерии оценивания: автоматические тесты, метрики качества кода и другие проверки. |
| UC-04 | Публикация задания         | Преподаватель делает задание доступным студентам.                                                            |
| UC-05 | Изменение задания          | Преподаватель изменяет условия задания, критерии оценки или дедлайн.                                         |

## 2. Управление отправками (Submission Management)

**Акторы:** Student.

| ID    | Сценарий                       | Описание                                                                                                     |
|-------|--------------------------------|--------------------------------------------------------------------------------------------------------------|
| UC-06 | Просмотр доступных заданий     | Студент просматривает опубликованные задания и их условия.                                                   |
| UC-07 | Отправка решения               | Студент загружает исходный код для конкретного задания.                                                      |
| UC-08 | Проверка допустимости отправки | Система проверяет, опубликовано ли задание, не истёк ли дедлайн и имеет ли студент право отправлять решение. |
| UC-09 | Повторная отправка решения     | Студент отправляет новую версию решения, чтобы улучшить результат.                                           |
| UC-10 | Просмотр истории отправок      | Студент просматривает все свои попытки, даты отправки и результаты проверок.                                 |
| UC-11 | Просмотр результата            | Студент просматривает полученную оценку и результаты отдельных проверок.                                     |

## 3. Автоматическая проверка решений (Grading & Execution)

**Акторы:** Student (инициатор косвенно), Professor, Grading System.

| ID    | Сценарий                            | Описание                                                                                   |
|-------|-------------------------------------|--------------------------------------------------------------------------------------------|
| UC-12 | Запуск решения                      | Система запускает загруженный исходный код в изолированной среде исполнения.               |
| UC-13 | Выполнение автоматических тестов    | Система проверяет решение с использованием тестов, определённых преподавателем.            |
| UC-14 | Сбор метрик                         | Система собирает дополнительные метрики качества решения, если они предусмотрены заданием. |
| UC-15 | Расчёт оценки                       | Система рассчитывает итоговую оценку на основании критериев преподавателя.                 |
| UC-16 | Сохранение результатов проверки     | Система сохраняет результаты выполнения, оценки, ошибки и связанные данные.                |
| UC-17 | Просмотр результатов преподавателем | Преподаватель просматривает результаты проверок и оценки студентов.                        |

## 4. Обнаружение плагиата (Plagiarism Detection)

**Акторы:** Plagiarism Detection System, TurnItIn, Professor.

| ID    | Сценарий                           | Описание                                                                                                |
|-------|------------------------------------|---------------------------------------------------------------------------------------------------------|
| UC-18 | Сравнение отправок между собой     | Система сравнивает решения студентов одного или нескольких заданий для обнаружения возможного плагиата. |
| UC-19 | Отправка решения в TurnItIn        | Система передаёт исходный код во внешний сервис TurnItIn для проверки.                                  |
| UC-20 | Получение результата TurnItIn      | Система получает результат внешней проверки и сохраняет его.                                            |
| UC-21 | Просмотр подозрительных совпадений | Преподаватель просматривает обнаруженные совпадения и результаты проверки.                              |

## 5. Интеграция с LMS (LMS Integration)

**Акторы:** LMS, Student, Professor.

| ID    | Сценарий                      | Описание                                                                                                  |
|-------|-------------------------------|-----------------------------------------------------------------------------------------------------------|
| UC-22 | Синхронизация студентов       | Система получает информацию о студентах из LMS.                                                           |
| UC-23 | Синхронизация заданий         | Система получает или передаёт информацию о заданиях через LMS (в зависимости от возможностей интеграции). |
| UC-24 | Передача оценок в LMS         | Система передаёт полученные оценки в LMS.                                                                 |
| UC-25 | Получение информации о курсах | Система получает информацию о курсах и принадлежности студентов к ним.                                    |

## 6. Аудит и история (Audit & Compliance)

**Акторы:** Admin, Auditor.

| ID    | Сценарий                        | Описание                                                                                                          |
|-------|---------------------------------|-------------------------------------------------------------------------------------------------------------------|
| UC-26 | Просмотр истории изменений      | Администратор или аудитор просматривает историю изменений заданий, критериев оценивания и других значимых данных. |
| UC-27 | Просмотр истории проверок       | Аудитор получает информацию о том, когда, кем и с использованием каких критериев выполнялась проверка.            |
| UC-28 | Получение аудиторского отчёта   | Аудитор получает отчёт об оценках, отправках и результатах проверок за определённый период.                       |
| UC-29 | Восстановление контекста оценки | Система позволяет восстановить, на основании каких исходных данных и правил студент получил конкретную оценку.    |

## 7. Администрирование (Administration)

|-------|---------------------------|------------------------------------------------------------------------------------|
| UC-30 | Управление пользователями | Администратор управляет учётными записями и ролями пользователей.                  |
